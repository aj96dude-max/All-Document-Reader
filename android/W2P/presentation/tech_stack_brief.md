# OfflineDocConverter: Tech Stack & Architecture Brief

## Core Language
*   **Kotlin**: The primary programming language used for the module. We leverage Kotlin Coroutines and Flows extensively to achieve robust, non-blocking asynchronous operations and memory-efficient stream processing.

## Architecture & Design Patterns
*   **Factory Pattern (`DocumentParserFactory`)**: Dynamically resolves the appropriate parsing strategy based on the file extension (or MIME type). This ensures the module is easily extensible for future formats.
*   **Unified Data State (`UnifiedDocumentState`)**: A sealed class representing the parsed document, abstracting away the differences between formats (HTML vs. raw text streams) so the rendering engine can operate consistently.
*   **Stream-based Processing**: For lightweight formats (`.txt`, `.csv`, `.tsv`, `.rtf`), we use standard `BufferedReader` combined with Kotlin `Flow` to process files line-by-line. This avoids loading massive files into RAM, completely eliminating `OutOfMemoryError` (OOM) risks.

## Libraries & Native Components

### 1. Mammoth (org.zwobble.mammoth)
*   **Purpose**: Used exclusively for parsing `.docx` files.
*   **Brief**: Mammoth converts complex Word documents into clean, semantic HTML. It focuses on meaning rather than exact layout, which makes it perfect for feeding into our rendering engine.

### 2. Android Native XML & ZIP APIs (`XmlPullParser`, `ZipInputStream`)
*   **Purpose**: Used to parse modern PowerPoint (`.pptx`) and Excel (`.xlsx`) files securely and efficiently.
*   **Brief**: These modern formats are essentially ZIP archives of XML files. By unzipping them on the fly and using Android's native `XmlPullParser`, we extract text directly from the slides or worksheets without loading any heavy third-party libraries (like Apache POI), keeping the APK size small and performance high. Specifically for `.xlsx`, we use a two-pass stream to extract shared strings and map them to worksheet rows.

### 3. Android WebView (`android.webkit.WebView`)
*   **Purpose**: The rendering engine for `.docx` (HTML) content.
*   **Brief**: We harness the powerful native Chromium-based WebView engine in an off-screen, headless manner to layout the HTML generated by Mammoth. We instruct the WebView to perform a "slow whole document draw" to accurately capture the full document length.

### 3. Android Native PDF Engine (`android.graphics.pdf.PdfDocument`)
*   **Purpose**: The single source of truth for PDF generation across all formats.
*   **Brief**: 
    *   For **DOCX**, the off-screen WebView draws its rendered layout directly onto the `PdfDocument` Canvas.
    *   For **Text & CSV/TSV**, we bypass the WebView overhead entirely and draw text line-by-line natively onto the Canvas using standard Android `Paint` APIs. This dual-approach guarantees the lowest possible memory overhead depending on the input format.

### 4. Kotlin Coroutines (`kotlinx.coroutines`)
*   **Purpose**: Asynchronous execution and threading.
*   **Brief**: Ensures that all heavy I/O operations (file reading, HTML conversion, and PDF rendering) execute on background threads (like `Dispatchers.IO`), keeping the Android UI completely responsive.
